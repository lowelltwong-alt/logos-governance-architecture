# Postflight Role Recovery

Use only after a valid postflight completeness audit finds a role that was absent
during the work.

For each missing role determine:

- exact affected claims and descendants;
- unique error class and likely decision value;
- why existing checks were insufficient;
- whether the role can now be independently qualified and given source access;
- whether the result is low/medium descriptive evidence or a high/frontier
  doctrine, authority, tradition, rights, or architecture question.

If material and staffable, quarantine the affected outputs, run one bounded
role plus its distinct checker, replay downstream validations, and issue a new
postflight audit. If material but unstaffable, block and create a human decision
packet. If not material, record `OMIT_WITH_REASON` and require independent
acceptance. One recovery round is allowed without changed evidence. Never
silently patch a result, invent a credential, or self-promote the new role.
